# Multi-Asset Telegram Sentiment Pipeline

Этот каталог содержит независимый pipeline для повторения эксперимента с Telegram sentiment уже не только для BTC, но и для альтернативных активов. Мы не меняем текущий BTC-код, поэтому все новые скрипты и результаты лежат в `multi_asset/`.

## Зачем
- сравнить сигналы между BTC, ETH и SOL;
- проверить устойчивость методологии на других токенах;
- подготовить отдельные артефакты (datasets, отчёты по корреляциям и ML).

## Структура
```
multi_asset/
  README.md              — описание.
  run_asset_pipeline.py  — основной скрипт.
  output/
    ETH/
    SOL/                 — появятся после запуска, хранят данные/метрики.
```

## Запуск
```
source venv/bin/activate  # если ещё не активирована
python multi_asset/run_asset_pipeline.py --assets ETH SOL
```

Скрипт автоматически:
1. Загружает объединённые TBSA-сообщения (`data/all_messages_tbsa.csv`).
2. Выделяет сообщения для выбранных активов по тикеру/синонимам.
3. Строит почасовые фичи (аналог `scripts/19_feature_engineering.py`).
4. Скачивает ценовые ряды из Yahoo Finance и объединяет их с фичами.
5. Проводит станцийарность, корреляции (HAC + FDR) и train/test разбиение.
6. Обучает Lasso/Ridge/ElasticNet на лаговых фичах и сохраняет метрики.

> **Важно:** скрипту нужен интернет-доступ для скачивания ETH/SOL котировок через `yfinance`.

## Артефакты на выходе
Для каждого актива создаются файлы:
- `messages.csv` — исходные сообщения, попавшие в отбор.
- `hourly_features.csv` — агрегированные фичи.
- `market_merged.csv` — объединённые данные «фичи + рынок».
- `univariate_analysis.json` — результаты стадий станцийарности/FDR.
- `ml_results.json` — метрики моделей на returns и volatility.

## Расширение списка активов
Передать свои тикеры можно через `--assets` (значения: `BTC`, `ETH`, `SOL`). Конфигурации (синонимы, тикеры, Yahoo-символы) описаны прямо в скрипте и легко дополняются.
